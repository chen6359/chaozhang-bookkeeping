# 朝账｜AI 宫廷记账原型

这是“AI 趣味记账产品”的可运行低保真原型。它不是视觉成品，而是用来验证一个核心闭环：

> 现实财务行为改变虚拟世界；虚拟世界再帮助用户看懂问题、做出调整并获得持续反馈。

本阶段只验证状态规则、信息结构和完整任务路径，不评价角色美术、场景冲击力、动效或最终奖励感。

## 建议体验路径

### 演示模式（约 4 分钟）

1. 进入“体验完整演示”。
2. 记录“夜宵118元”并确认候选账目。
3. 总支出由 ¥1,892 变为 ¥2,010，超过 ¥2,000 消费池 ¥10。
4. 虚拟国库由 ¥5 变为 -¥5，府邸进入破损状态。
5. 在同一个风险奏折里同时查看太监急报、户部尚书谏言和皇后宽慰。
6. 查看风险奏折，留下一个议事选择并完成县署朝会。
7. 第四步会根据当前亏空自动生成一笔足以让国库回正的演示储蓄；标准路径为 ¥100，国库由 -¥5 回升至 ¥95。

### 真实模式（约 5 分钟）

1. 进入“我的账本”。
2. 将本周期收入分为“消费池”和“初始国库”，两项合计等于收入。
3. 将消费池完整分配给餐饮、住房、交通、医疗、购物和娱乐。
4. 设置储蓄目标、日期和建设场景。
5. 记录、编辑或删除账目，观察分类预算、消费池和国库账面的联动。
6. 刷新页面，检查本地数据是否保留。

## v0.2 核心规则

- 本产品只记账，不连接银行卡，不接收、兑换、保管或划转真实资金。
- 单个分类超支只触发提醒，不会自动挪用其他分类或真实储蓄。
- 无法识别分类的支出会进入“其他／待分类”，但仍完整计入总支出、消费池超支和国库。
- 只有总支出超过消费池时，超出部分才影响虚拟国库：

  `国库余额 = 期初国库 + 新增储蓄 − max(总支出 − 消费池, 0)`

- 国库允许为负数，负数跨周期保留；系统不会凭空补齐。
- 后续新增储蓄会先使负数回升，国库回正后破损场景随之修复。
- 财务平稳、动用国库、财政亏空对应三种不同的世界状态。
- 高风险反馈在同一界面一次展示三个角色；普通事件可展示一人或两人。
- 朝会每满七天生成一次推送，由用户自行开启，不要求固定时间参加。

## AI 与程序的边界

- 程序负责金额、预算比例、超支和国库余额的确定性计算。
- AI 负责把这些事实转成角色化表达和可执行建议。
- 聊天输入先生成候选账目，用户确认后才写入。
- 原型使用规则模拟 AI 解析，不调用真实大模型服务。

## 当前发布方式

- 源代码保存在 GitHub 仓库。
- 网页由 GitHub Pages 自动构建和发布，不再使用 Codex Sites。
- 用户账本保存在当前浏览器的本地存储中；更换浏览器、设备或清理网站数据后不会自动同步。

## 当前明确不做

- 真实资金托管、自动扣款或银行卡连接。
- 账号、云同步和跨设备自动迁移。
- 自动判断用户是否执行了朝会中选择的现实行动。
- 用未经验证的阈值或政绩分数宣称能够培养储蓄习惯。
